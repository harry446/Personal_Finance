# M7 authorization matrix

Every protected request derives the user from the Auth.js session. Browser input never carries an authoritative user ID. An unknown, foreign, or nested foreign ID is handled as an unavailable record; no operation may disclose whether another user owns it.

| Resource and entry point                                                      | Positive coverage                                                      | Negative coverage                                                                                                                    |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Authenticated app pages: Overview, Transactions, Categories, Imports, Budgets | Each server page calls requireCurrentUser before its read              | Unauthenticated Playwright redirect; no page accepts a user ID                                                                       |
| Dashboard API                                                                 | Session user ID is the only query scope                                | dashboard-route.test.ts supplies a foreign browser userId and receives 401                                                           |
| Categories: list, create, rename, archive, restore                            | Authorization matrix integration fixture operates on owner categories  | Foreign direct category ID is rejected for rename, archive, restore, ledger create/update, import candidate update, and budget setup |
| Manual ledger: list, create, update, delete                                   | Owner transaction is created/read/updated/deleted in integration tests | Foreign transaction ID is rejected for update/delete; foreign category cannot be used for create/update                              |
| Budget setting and month configuration                                        | Owner can enable mode and configure an active owned category           | Foreign category cannot create a budget; owner setting cannot mutate another user                                                    |
| Import batches: history, review queue, direct batch read                      | Owner sees only its own batches and retrieves its own batch            | Foreign batch ID is rejected                                                                                                         |
| Import candidates: update and selection                                       | Owner can update/select a candidate belonging to its ready batch       | Candidate lookup scopes through import_batch.user_id, rejecting foreign nested IDs                                                   |
| Import approval                                                               | Owner can finalize selected rows atomically                            | Foreign batch approval is rejected before candidate or ledger reads                                                                  |
| Multipart import API                                                          | Authenticated session user is passed to the extraction service         | Unauthenticated request is rejected before multipart parsing; request and user rate limits run before processing                     |
| Retention trigger                                                             | Valid deployment bearer token runs the purge                           | Missing or non-matching token returns 401 with no purge                                                                              |
| Health check                                                                  | Performs only a fixed SELECT 1 and returns status                      | Does not expose database details on failure                                                                                          |

The database-backed matrix is exercised in tests/integration/authorization-matrix.test.ts. Route and action tests additionally prove that their handlers derive the session user rather than trusting browser-provided identifiers.
